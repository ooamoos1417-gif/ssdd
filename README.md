# منصة ملفات إنجاز المعلمين (SaaS)

منصة إلكترونية عربية (RTL) لملفات إنجاز المعلمين، **بدون تسجيل ذاتي** — الأدمن وحده ينشئ كل حساب بعد استلام الاشتراك. مبنية بـ HTML/CSS/JS خالص + Supabase (مصادقة حقيقية، قاعدة بيانات، تخزين ملفات).

## 🔑 المبدأ الأساسي: لا يوجد تسجيل ذاتي إطلاقًا

- **لا توجد صفحة Sign Up ولا Register ولا Forgot Password** في كامل المشروع.
- الصفحة الوحيدة للمصادقة هي `index.html` (تسجيل الدخول فقط).
- الأدمن ينشئ حساب كل معلم يدويًا من `admin.html` بعد استلام الدفعة، ثم يرسل له البريد وكلمة المرور بنفسه (واتساب، بريد إلكتروني، إلخ) — التطبيق لا يرسل شيئًا تلقائيًا.
- معطّل أيضًا على مستوى Supabase نفسه (خطوة إعداد إلزامية أدناه) كطبقة حماية إضافية، حتى لا يقدر أحد يسجّل حسابًا عبر استدعاء مباشر لواجهة Supabase من خارج التطبيق.

## 📄 الصفحات

| الصفحة | الوصف |
|---|---|
| `index.html` | تسجيل الدخول (فقط) |
| `dashboard.html` | لوحة المعلم: الشواهد، الجدول، الشهادات، الدورات، الزيارات، التقييم، تصدير PDF، مشاركة الملف |
| `admin.html` | لوحة الأدمن: إنشاء/تعديل/حذف/إيقاف حسابات المعلمين، تجديد الاشتراكات، الإشراف على روابط المشاركة، مساحة التخزين |
| `share.html?token=...` | عرض قراءة فقط لملف معلم — **بدون أي تسجيل دخول** |

## 🚀 خطوات الإعداد (بالترتيب)

### 1) أنشئ مشروع Supabase
1. أنشئ مشروعًا مجانيًا على [supabase.com](https://supabase.com)
2. **عطّل التسجيل الذاتي** (مهم جدًا): من **Authentication → Providers → Email**، أطفئ **"Allow new users to sign up"**. هذا يمنع إنشاء أي حساب إلا عبر Admin API (اللي يستخدمها هذا المشروع حصرًا)
3. من **SQL Editor** نفّذ ملف `sql/schema.sql` بالكامل مرة واحدة — ينشئ كل الجداول، سياسات الأمان (RLS)، دالة `is_admin()`، المُشغّل (trigger) التلقائي لإنشاء الملف الشخصي، دالة المشاركة العامة `get_shared_portfolio`، وحاوية التخزين
4. من **Project Settings → API** انسخ: `Project URL`، `anon public key`، و`service_role key` (سرّي)

### 2) أنشئ أول حساب أدمن (أنت)
لا توجد واجهة لإنشاء أول أدمن (منطقي، لأنه لا يوجد تسجيل ذاتي). أنشئه يدويًا مرة واحدة فقط من **SQL Editor**:

```sql
-- الخطوة أ: أنشئ المستخدم من Authentication → Users → Add User في لوحة Supabase
-- (أدخل بريدك وكلمة مرورك، وفعّل "Auto Confirm User")

-- الخطوة ب: بعد إنشائه، نفّذ هذا الاستعلام لتحويله لأدمن
-- (المُشغّل التلقائي أنشأ له profile+account بدور 'teacher' افتراضيًا، نعدّله هنا)
update public.accounts set role = 'admin' where id = (
  select id from auth.users where email = 'ضع-بريدك-هنا@example.com'
);
```

بعدها سجّل دخولك بنفس البريد وكلمة المرور من `index.html`، وستُوجَّه تلقائيًا إلى `admin.html`.

### 3) أضف بيانات الاتصال في الكود
افتح `js/supabase-client.js` وضع القيم:
```js
const SUPABASE_URL = "https://YOUR-PROJECT-REF.supabase.co";
const SUPABASE_ANON_KEY = "YOUR-ANON-PUBLIC-KEY";
```

### 4) أضف متغيّر البيئة السرّي (لدالة الخادم الوحيدة)
هذا المشروع يحتاج **دالة خادم واحدة فقط** (`api/admin/teachers.js`) — لأن إنشاء/حذف حساب مصادقة حقيقي يتطلّب `service_role key`، وهذا المفتاح لا يجوز أبدًا وضعه في كود يعمل بالمتصفح.

من **Vercel → Project Settings → Environment Variables** أضف (انظر `.env.example`):
```
SUPABASE_URL=https://YOUR-PROJECT-REF.supabase.co
SUPABASE_SERVICE_ROLE_KEY=...
```

### 5) انشر المشروع
ارفع المجلد على GitHub، ثم استورده في [vercel.com](https://vercel.com) (Vercel يكتشف مجلد `api/` تلقائيًا كدالة خادم — لا حاجة لأي إعداد بناء (Build) لأن باقي الموقع HTML/CSS/JS ثابت).

## 👩‍🏫 آلية عمل الأدمن اليومية

1. تستلم دفعة اشتراك من معلم
2. تفتح `admin.html` → **حسابات المعلمين** → **+ إنشاء حساب معلم**
3. تعبّي الاسم والبريد، تضغط **توليد** لكلمة مرور قوية عشوائية (أو تكتب واحدة بنفسك)، تحدّد تاريخ انتهاء الاشتراك
4. تضغط **إنشاء الحساب** — يُنشأ الحساب فورًا في Supabase
5. **تنسخ البريد وكلمة المرور وترسلهما للمعلم بنفسك** (لا يُرسل أي بريد تلقائي من النظام)
6. لاحقًا: من نفس الجدول تقدر **تعدّل** بيانات المعلم أو حالة اشتراكه، **توقف** حسابه مؤقتًا (يمنعه من الدخول فورًا دون حذف بياناته)، أو **تحذفه نهائيًا**

## 🔗 نظام مشاركة الملف

- زر **"إنشاء رابط مشاركة"** موجود في لوحة المعلم (الرئيسية + قسم مخصّص "مشاركة الملف")
- يولّد المعلم توكنًا عشوائيًا بتشفير 256-بت (`crypto.getRandomValues`) — غير قابل للتخمين إطلاقًا
- يحدّد صلاحية الرابط (أسبوع / شهر / 3 أشهر / بدون انتهاء)
- الرابط الناتج (`share.html?token=...`) **للعرض فقط** — يُفتح عبر دالة قاعدة بيانات آمنة (`get_shared_portfolio`، بصلاحيات `SECURITY DEFINER`) تتحقق من صلاحية الرابط أولًا (غير معطّل، غير منتهٍ) قبل إرجاع أي بيانات، ولا تسمح بأي تعديل أو حذف أو رفع من هذه الصفحة على الإطلاق (لا توجد أي دالة كتابة مربوطة بها)
- المعلم يقدر **يعطّل** أي رابط فورًا من قسم "مشاركة الملف" في لوحة تحكمه، أو **يحذفه** نهائيًا
- الأدمن يشرف على كل الروابط من `admin.html` → **روابط المشاركة** (يقدر يعطّل أي رابط من أي معلم)

## 🔒 نموذج الأمان

- **مصادقة حقيقية عبر Supabase Auth** (وليست محاكاة) — الجلسات، انتهاء الصلاحية، وكل شيء يُدار من طرف Supabase نفسه
- **فصل صارم بين `profiles` (يعدّله المعلم) و`accounts`** (الدور، الاشتراك، الإيقاف — **admin فقط** يقدر يكتب فيه، مفروض عبر RLS)
- **كل الجداول محمية بـ Row Level Security**: كل معلم يرى ويعدّل بياناته فقط؛ الأدمن يرى/يدير الكل عبر دالة `is_admin()` آمنة
- **دالة خادم واحدة فقط** (`api/admin/teachers.js`) — تتحقق من هوية المستدعي عبر توكن الجلسة، ثم من دوره في `accounts`، قبل أي عملية إنشاء/حذف حساب
- **حاوية التخزين محمية بمسار المستخدم**: كل معلم يرفع/يقرأ/يحذف فقط داخل مجلد باسم معرّف حسابه
- **الرابط العام للمشاركة قراءة فقط بلا استثناء** — الدالة `get_shared_portfolio` لا تحتوي أي أمر `INSERT`/`UPDATE`/`DELETE` على بيانات المعلم (فقط تحديث عدّاد المشاهدة الخاص بالرابط نفسه)

## ✨ ملاحظة حول عدد دوال الخادم

هذا المشروع يحتاج **دالة خادم واحدة فقط** — عمدًا، لتفادي حد Vercel Hobby (12 دالة كحد أقصى). كل شيء آخر (قراءة/كتابة بيانات المعلم، إدارة روابط المشاركة، عرض القوائم في لوحة الأدمن) يتم مباشرة من المتصفح عبر Supabase JS SDK، بأمان كامل بفضل RLS — بدون الحاجة لأي دالة وسيطة إضافية.
